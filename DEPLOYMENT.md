# Deployment — Static S3 Site

## Deployment contract

The production artifact is the complete `dist/` directory generated by Vite. The target currently documented for this project is S3 bucket `retirement-planner` in AWS account `891117574729`, region `eu-west-1`. Treat these as expected values to verify, not as proof that the active CLI session or bucket is correctly configured.

The app has no backend: scenarios and column order remain in each browser's `localStorage` and do not move between browsers or devices. There is no supported export/import, authentication, or IP-lock feature. A public S3 website endpoint is HTTP-only; use CloudFront (or another HTTPS-capable static host) with an ACM certificate for production privacy and integrity.

## Reproducible preflight

Run from the repository root in PowerShell, from a clean reviewed commit:

```powershell
npm ci
npm run check
npm run build
```

`npm ci` installs exactly from `package-lock.json`; do not deploy a build made from a stale `node_modules`. `npm run check` is the mandatory gate: it runs the full Node test suite and then creates a production build. Stop deployment if either step fails.

Verify the artifact contains `dist/index.html` and hashed files under `dist/assets/`. Do not edit `dist/` by hand.

## Verify AWS identity and target

```powershell
$ExpectedAccount = '891117574729'
$Region = 'eu-west-1'
$Bucket = 'retirement-planner'
$Account = aws sts get-caller-identity --query Account --output text
if ($Account -ne $ExpectedAccount) { throw "Wrong AWS account: $Account" }
aws s3api head-bucket --bucket $Bucket --region $Region
$Versioning = aws s3api get-bucket-versioning --bucket $Bucket --region $Region --query Status --output text
if ($Versioning -ne 'Enabled') { throw 'Bucket versioning must be enabled before deployment.' }
```

Always pass `--region eu-west-1`; do not rely on a profile's default. Enabling versioning or changing public-access, bucket-policy, CloudFront, DNS, or certificate settings is an infrastructure change and must be separately reviewed.

## Dry run and release

Review deletions and uploads before changing S3:

```powershell
aws s3 sync dist/ s3://retirement-planner/ --delete --dryrun --region eu-west-1 --cache-control 'public, max-age=3600'
```

Only after the dry-run output matches the reviewed `dist/` artifact, repeat without `--dryrun`:

```powershell
aws s3 sync dist/ s3://retirement-planner/ --delete --region eu-west-1 --cache-control 'public, max-age=3600'
```

`--delete` can remove deployed objects absent from `dist/`; versioning is the safety net, not permission to ignore the dry run. Prefer immutable release prefixes plus a controlled CloudFront origin switch for atomic releases; root sync is not atomic.

## Smoke check

Use the HTTPS distribution URL when available. In a fresh/private browser context:

1. Load the page with no console or failed asset requests.
2. Run the default scenario and confirm the chart, annual table, and quarter expansion render.
3. Change an input and rerun; confirm output changes and no `NaN` appears.
4. Save and reload a temporary scenario in the same browser, then delete it; confirm no cross-device persistence is implied.
5. Check direct navigation and refresh, desktop/mobile layout, and HTTPS with no mixed content.

## Rollback

Record the source commit for every deployment. The preferred rollback is to check out the last known-good commit, run the same `npm ci` → check → build sequence, dry-run the sync, and redeploy it; bucket versioning preserves overwritten/deleted object history for recovery. For an urgent object-level recovery, identify exact prior version IDs with `aws s3api list-object-versions` and restore them deliberately—never bulk-delete versions or delete markers without a reviewed recovery plan. Re-run the smoke check after rollback.
